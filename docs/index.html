Deployment Modes

Three Ways to Govern

The platform meets teams where they work — local tooling, GitHub automation, and an optional visibility layer — without requiring a new process or tool.

Local Developer CLI

Validate governance, preview prompt rewrites, run dry-run syncs, and catch compliance issues before they reach a PR — from the terminal with copilot-gov.sh or copilot-gov.ps1.

GitHub PR Automation

Central governance synced to all target repos through PR-based automation. Manifest-tracked removals, drift detection, and override preservation on every sync cycle.

Coverage Dashboard

Optional visibility layer — repo onboarding coverage, governance drift, deny-rule violations, and prompt workflow usage. Planned for the platform team; not required for pilot.

Core Capabilities

What the Platform Does

Eight interlocking capabilities that together make AI-assisted development safe, consistent, and auditable.

Instruction Sync

Central baseline synced to every repo. Manifest-tracked so deleted rules are cleaned up — no orphaned governance.

Prompt Interception

Every prompt governed before the model sees it. Developer wording preserved verbatim; context and rules are injected.

Security Guardrails

No hardcoded secrets, no PII logging, no auth bypass, OWASP prevention — at the prompt layer, not just in review.

Code Quality Gates

Guardrails against console logs, debug artifacts, and linting anti-patterns — 80% reduction in review noise targeted.

Local CLI Tooling

doctor, validate, audit, rewrite — token budget enforcement and placeholder detection before the pre-commit hook.

Reusable Workflows

14 approved .prompt.md workflows for common fixes. 40–60% less repeated context per fix request.

Override Safety

Repo-specific sections always preserved. Overrides may extend rules but cannot weaken security or compliance guardrails.

Audit & Reporting

Drift fixed within one sync cycle. CODEOWNERS gates every governance PR. Telemetry tracks interception events and deny-rule hits.

Platform Architecture

Design at a Glance

Key structural decisions — from the central baseline to the interception kernel to the override model.

Platform
Copilot Governance Platform — central repo naresh-fd/copilot-governance is the source of truth for all governed content.
Purpose
Reduce repeated AI token waste, enforce secure coding guardrails, and give teams reusable approved workflows for common fixes.
Governance Files
copilot-instructions.md (repo-wide) · instructions/*.instructions.md (path-specific) · prompts/*.prompt.md (approved workflows)
Sync Engine
PR-based sync to each target repo. .copilot-governance-manifest tracks shipped files so centrally deleted rules are removed downstream without touching repo-added content.
Interception Kernel
prompt-core/ + hooks/. rewrite.mjs intercepts via UserPromptSubmit — developer wording carried verbatim, governance injected. All deny rules ship in shadow mode.
Security Layer
No hardcoded secrets, no PII logging, no bypass of auth or compliance gates, OWASP injection prevention, secure error handling — enforced at prompt time.
Override Model
Central managed section (between governance markers) owned by this repo. Repo override section always preserved. Overrides may add local context, never weaken security or compliance rules.
CLI Commands
doctor · validate · audit · sync --dry-run · sync --apply · prompt <name> · rewrite "<text>" · report · install-hooks

Known Gaps

JetBrains has no hook support. Java and Spring Boot teams in IntelliJ get instruction files only — no rewriting, no injection, no deny rules, no telemetry. These are also the teams carrying java-security, the only high-risk intent requiring human security review. The teams with the highest-risk prompts have the weakest coverage. Raise with Java teams by name; carry as a named accepted risk with an owner.

Hooks are a guardrail, not a security control. A developer can disable hooks; a timeout always fails open. Real enforcement requires an MDM policy push — a desktop-engineering workstream this repo cannot deliver alone. Treat interception as strong assistance, not an auditable control.

No central telemetry collection. report reads only the local machine's file — deliberate for privacy, but the platform cannot demonstrate estate-wide that interception is running. Central collection is a Wave 1 prerequisite and carries its own employee-monitoring questions.

Hook APIs are Preview — re-verify quarterly. The v1 kernel was built against a schema that did not exist; nothing caught it for a full phase. surfaces.json carries a verifiedOn date — treat it as an expiry, not a footnote. Last verified: 2026-08-02.

Security

Non-Negotiable Guardrails

These rules are enforced at the prompt layer. They cannot be weakened by repo overrides.

No Hardcoded SecretsNever generate passwords, tokens, API keys, certificates, connection strings, or session identifiers. Approved secret-management patterns only.

No PII LoggingNever log customer data, account numbers, card numbers, secrets, session IDs, request payloads, or auth headers — regardless of log level.

No Bypass InstructionsNever suggest bypassing auth, MFA, dual-control, audit logging, SAST, dependency scanning, linting, or tests.

Input ValidationValidate and sanitize all external input. Prevent SQL injection, XSS, CSRF, path traversal, unsafe deserialization, and CORS misconfigurations.

Secure Error HandlingNever expose stack traces, internal paths, or sensitive system internals to end users. Errors explain what went wrong, not how the system works.

Human Review FlagsFlag auth, encryption, payment processing, audit logging, and PII-related changes for mandatory security review.

RefuseUse Instead

Medium Risk
RefuseUse Instead

Prompt Governance

Approved Reusable Workflows

Developers invoke these from the IDE or CLI instead of writing long prompts from scratch. Each workflow references the repo's governance instructions and security baseline.

/fix-pr-review /fix-security-finding /fix-console-logs /fix-sonarqube-issue /fix-eslint-issue /fix-test-failure /fix-build-failure /fix-typescript-error /fix-angular-migration /fix-react-code-quality /fix-java-springboot-security /generate-unit-tests /document-repo /explain-legacy-code
Each workflow must reference the repo's Copilot instructions and the security baseline.
Each workflow must include task scope, rules, verification expectations, and summary format.
Workflows must not instruct developers to bypass tests, linting, scans, review, or compliance gates.
Security-sensitive workflows must include human review callouts.
